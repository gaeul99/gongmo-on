# 공모온 (Gongmo-On)

공모전 지원자를 위한 아이디어 분석 웹 서비스입니다.

아이디어를 입력하면 AI가 공모전 적합도를 분석해 추천 공모전과 개선점을 알려 주고, 유형 검사·대시보드·연습 노트로 응모 준비 전 과정을 돕습니다.

## 서비스 소개

**공모온**은 공모전에 도전하고 싶지만 준비와 도전이 어려운 **누구나**를 위한 AI 아이디어 분석·공모전 추천 서비스입니다. 공모전에 도전할 때는 세 가지 벽에 부딪힙니다.

1. **"아이디어는 있는데, 어디에 내야 할지 모른다."** — 공모전 정보는 위비티·콘테스트코리아 등 여러 사이트에 흩어져 있고, 나의 아이디어와 맞는지 판단하기 어렵습니다.
2. **"아이디어가 괜찮은지 스스로 판단하기 어렵다."** — 강점과 약점, 심사위원이 볼 차별점을 객관적으로 짚어 줄 창구가 없습니다.
3. **"출품 직전이 가장 막막하다."** — 서류를 쓰고 예상 질문을 준비하는 '마지막 한 걸음'을 도와주는 도구는 거의 없습니다.

근원은 정보 부족 그 자체보다 **'나를 모른 채' 준비한다는 것**입니다. 공모온은 이 세 가지를 각각 **공모전 추천 → 아이디어 분석(제안서 초안 포함) → 연습 노트**로 풀어, 준비 과정 전체를 하나의 흐름으로 연결합니다. 모든 준비는 **유형 검사로 진단한 나의 성향**에서 시작해 힌트 → 분석 → 추천 → 연습 노트까지 이어지며, 기존 공모전 사이트에 없는 '내 성향' 진단(**유형 검사**)이 차별화 요소입니다.

```
유형 검사 (20문항) → 아이디어 입력 → AI 분석 · 추천 공모전 → 연습 노트 → 대시보드
```

| 기존 공모전 사이트 | 공모온 |
| --- | --- |
| 공모전 목록만 제공 | 아이디어 분석 → 추천 → 준비 → 기록까지 전 과정 |
| 검색은 키워드에 의존 | 아이디어 내용 기반 AI 적합도·추천 이유 제공 |
| 준비는 각자의 몫 | 제안서 초안 생성, 심사 의문 연습 노트 제공 |
| 도전 이력 관리 없음 | 대시보드로 도전 히스토리·출품 로드맵 시각화 |

> **'응모 완료'는 실제 응모와 분리된 기록 기능입니다.** 공모온에서 응모를 기록해도 실제 응모는 반드시 해당 공모전 사이트에서 진행하도록 2단계 확인으로 안내하며, 접수가 마감된 공모전도 이미 제출을 마친 응모라면 기록으로 남길 수 있습니다.

## 기술 스택

| 영역 | 기술 |
| --- | --- |
| 화면(프론트엔드) | React 19 + TypeScript + Vite (SPA, 포트 5173) |
| 서버(백엔드) | Python 3.14 + FastAPI + uvicorn (포트 3000) |
| AI 분석 | OpenAI 호환 게이트웨이 연동 (모델: `openai/gpt-5.6-luna`) |
| 데이터 저장 | PostgreSQL 17 (Docker 컨테이너) + 브라우저 localStorage(1차 캐시) |
| 공모전 데이터 | 위비티·콘테스트코리아 자동 수집 (`backend/app/services/contest_sync.py`) |
| 테스트 | Vitest(프론트 26개) + pytest(백엔드 35개) = 총 61개 |
| 엑셀 내보내기 | exceljs (마감 달력 다운로드 — 프론트엔드) |
| 이메일 | Python 표준 라이브러리 smtplib (SMTP 미설정 시 콘솔·outbox 테이블 기록) |
| 배포 | Docker 단일 이미지(FastAPI+SPA 동시 서빙) + Render 블루프린트 |

## 사전 준비

- **Node.js 20.19 이상(22 LTS 권장)** — `node -v`로 확인. Vite 8이 이 버전대를 요구합니다.
- **Python 3.14** — `python --version`으로 확인. 백엔드 가상환경(.venv) 생성에 필요합니다.
- **Docker Desktop** — PostgreSQL 데이터베이스를 컨테이너로 실행하는 데 필요합니다.
- **npm** — Node.js 설치 시 함께 설치됩니다.
- **AI 분석용 API 키** — `backend/.env`에 설정(아래 환경변수 항목 참고). 키가 없어도 앱 자체는 동작하며, 분석 실행 시 미리 준비된 **데모 분석**으로 자동 대체됩니다.

## 설치 및 실행

### 방법 1 — 루트에서 한 번에 실행

```bash
npm install       # 루트 도구(concurrently) 설치
npm run setup     # 프론트엔드 의존성 설치 (백엔드는 npm 패키지 의존성이 없음)
cd backend
npm run venv      # 최초 1회 — Python 가상환경(.venv) 생성 + requirements 설치
npm run db:up     # PostgreSQL 컨테이너 기동 (Docker Desktop 필요)
cd ..
npm run dev       # 백엔드(3000) + 프론트엔드(5173) 동시 실행
```

### 방법 2 — 각자 다른 터미널에서 실행

```bash
# 1) 백엔드 (포트 3000)
cd backend
npm run venv      # 최초 1회
npm run db:up     # PostgreSQL 컨테이너 (Docker Desktop 필요)
npm run dev

# 2) 프론트엔드 (포트 5173) — 새 터미널에서
cd frontend
npm install
npm run dev        # http://localhost:5173
```

- 매번 수동 실행이 번거로우면 루트의 `start-dev.cmd`를 더블클릭하세요. Docker Desktop(꺼져 있으면 기동)→DB 컨테이너→백엔드·프론트엔드가 각각의 콘솔 창으로 뜨고(백엔드 venv가 없으면 자동 생성), 창을 닫으면 해당 서버가 종료됩니다. 이 파일의 바로 가기를 Windows 시작프로그램 폴더에 두면 PC 로그인 시 자동 실행됩니다.

### 백엔드 환경변수 (backend/.env)

| 키 | 필수 여부 | 설명 |
| --- | --- | --- |
| `DATABASE_URL` | 필수 | PostgreSQL 접속 정보. 기본값 `postgresql://gongmo:gongmo@localhost:5432/gongmo_on` |
| `OPENAI_API_KEY` | 필수 | AI 분석용 키. JWT 형태라 유효기간이 있고 만료 시 401 `expired_key` 발생 |
| `OPENAI_BASE_URL` | 필수 | OpenAI 호환 게이트웨이 주소 |
| `OPENAI_MODEL` | 필수 | `openai/gpt-5.6-luna` — 접두사(`openai/`)까지 정확히 기입 |
| `SMTP_HOST` 등 `SMTP_*`·`MAIL_FROM` | 선택 | 이메일 발송. 비어 있으면 실제 발송 없이 콘솔·outbox 테이블에만 기록 |
| `ADMIN_TOKEN` | 선택 | 공모전 강제 동기화·수동 마감 점검 등 관리 엔드포인트 인증(헤더 `x-admin-token`) |
| `CLIENT_ORIGIN` | 선택 | CORS 허용 출처(배포 시, 쉼표로 나열). 기본 `localhost:5173` |
| `CONTACT_EMAIL` | 선택 | 문의 수신 이메일(기본값 있음) |
| `PORT` · `STATIC_DIR` | 선택 | 배포용 — 서버 포트 변경, 빌드된 SPA를 같은 서버가 서빙하는 단일 배포 모드 |

전체 환경변수 설명은 `backend/README.md`(로컬 전용 — GitLab 미포함)를 참고하세요.

## 주요 기능

모든 기능의 재료는 **직접 수집한 실제 공모전 데이터**입니다 — 위비티·콘테스트코리아에서 접수 중·접수 예정 공모전을 **6시간마다 자동 수집**해 현재 **351건**이 쌓여 있고, 유사 사례·수상작 아카이브 **54건**을 더했습니다. 마감이 다가오는 공모전은 **D-7·D-3·당일에 알림**으로 알려 줍니다.

- **유형 검사** — 20문항·7유형으로 준비 성향을 진단하고 일치율(%)까지 보여 줍니다. 검사 결과는 아이디어 입력 화면의 힌트로 자동 채워집니다.
- **아이디어 입력 & AI 분석·추천** — AI가 아이디어를 분석해 한 줄 요약과 강점·보완점·심사 포인트·확장 아이디어를 알려 주고, 공모전마다 적합도(0~100)와 추천 이유를 붙여 상위 4건을 추천합니다. 공모전 제목·링크 같은 사실은 앱이 수집한 실제 DB가 담당하고 AI는 분석 문장만 만들며, 서버가 답변을 한 번 더 검사해 환각은 잘라냅니다. 분석 결과 화면에서는 제안서 초안(6섹션·TXT 다운로드)과 제출 전 자가 점검 체크리스트(8항목)까지 다룹니다.
- **연습 노트** — 심사위원이 기획서를 읽으며 품을 의문을 미리 답해 둔 노트입니다. 면접·발표가 없는 공모전은 답변이 기획서에 들어갈 문장이 되고, 있는 공모전은 그대로 발표 답변으로 씁니다.
- **공모전 탐색** — 검색·필터(접수 상태·분야·연령)·정렬과 12건씩 페이지로 탐색하고, 상세 페이지에서 마감 D-day·주최·접수 기간·참가 대상을 확인합니다. 아이디어 분석을 마친 사용자에게는 카드마다 적합도(%) 뱃지와 적합도순 정렬이 생깁니다. 찜·응모 기록 관리, NEW 배지, 전용 주소 공유를 지원합니다.
- **대시보드** — 접수 중 공모전·내 응모·찜·보관 아이디어 KPI와 마감 임박 목록, 응모 결과(진행 중·수상·탈락)가 쌓이는 도전 히스토리, 5단계 출품 로드맵을 한눈에 보여 줍니다.
- **마이페이지** — 회원가입·로그인(30일 유지), 회원정보 수정, 응모 기록·결과 기록, 알림 설정.

## 트러블슈팅

| 증상 | 해결 |
| --- | --- |
| `npm run dev`가 5173에서 띄워지지 않고 바로 실패함 | 5173을 쓰고 있는 프로세스를 종료하세요. `netstat -ano \| findstr :5173`으로 PID 확인 후 `taskkill /PID <번호> /F`. **포트를 바꾸는 것은 금지** — 아래 '데이터가 사라진 것처럼 보임' 항목 참고 |
| 계정·찜·아이디어 데이터가 사라진 것처럼 보임 | 브라우저 주소가 `http://localhost:5173`인지 확인하세요. 과거 키(`idea-navigation:` 등)는 앱 시작 시 자동 이전됩니다 |
| AI 분석 실행 시 401 "The key has expired" (`expired_key`) | 게이트웨이(mlapi.run)에서 토큰을 재발급받아 `backend/.env`의 `OPENAI_API_KEY`를 교체하고 백엔드를 재시작 |
| 분석 결과가 갑자기 '데모 분석'으로 표시됨 | 백엔드 콘솔의 오류 로그를 확인하세요. 대부분은 API 키 만료(위 항목) 또는 네트워크 문제입니다 |
| 이메일이 실제로 오지 않음 | 실제 발송이 필요하면 `backend/.env`에 `SMTP_HOST`·`SMTP_PORT`·`SMTP_USER`·`SMTP_PASS`·`MAIL_FROM`을 설정하고 재시작 |
| 공모전 목록이 비어 있거나 오래됨 | 서버가 켜져 있으면 주기적으로 자동 수집됩니다. 즉시 동기화는 `POST /api/contests/sync`(`Authorization: Bearer <ADMIN_TOKEN>` 필요)를 호출하세요. 백엔드 콘솔에 `[contestSync]` 로그가 찍힙니다 |
| 백엔드가 3000 포트에서 시작되지 않음 | 기존 백엔드 콘솔 창을 닫거나 `netstat -ano \| findstr :3000`으로 PID 확인 후 종료 |
| 백엔드가 시작되자마자 종료됨 | Docker Desktop을 켜고 backend 폴더에서 `npm run db:up` 후 다시 실행 |
| 사용자 데이터·계정을 모두 초기화하고 싶음 | 백엔드와 컨테이너를 끈 뒤 backend 폴더에서 `docker compose down -v`(볼륨까지 삭제)하고 `npm run db:up`으로 다시 올리면 빈 DB가 생성됩니다. **주의: 계정과 모든 기록이 지워지며 되돌릴 수 없습니다.** 평소에는 `npm run db:down`(볼륨 유지)으로 중지하세요 |
| `npm install` 또는 빌드·venv 생성이 실패함 | Node.js 20.19 이상(22 LTS 권장)·Python 3.14로 업그레이드 후 재시도 |
| gpt-5 계열 모델에서 `max_tokens`·temperature 오류 | `app/services/ai_service.py`가 모델명 접두사를 보고 자동 처리합니다. `OPENAI_MODEL`에 `openai/` 접두사가 정확히 들어갔는지만 확인하세요 |

## 배포

현재는 미배포 상태입니다(위 '배포 주소' 참고). 배포는 **Render 블루프린트 + Docker 단일 이미지** 기준으로 준비돼 있습니다.

1. **Render 블루프린트** — Render 대시보드에서 New + → Blueprint로 이 리포지토리를 선택하면 `render.yaml`대로 **웹 서비스와 PostgreSQL 데이터베이스가 함께** 생성되고, `DATABASE_URL`은 데이터베이스에서 자동 연결됩니다. 빌드는 루트 `Dockerfile`을 사용해, 프론트를 `vite build`한 뒤 그 산출물을 FastAPI 서버가 `STATIC_DIR`로 함께 서빙하는 **단일 서비스**로 배포합니다(API+화면이 같은 오리진이라 CORS·API 주소 설정이 필요 없음). 헬스 체크는 `/api/health`, 포트는 `PORT`(기본 3000)를 따릅니다.
2. **환경변수·시크릿** — 블루프린트 생성 과정에서 `OPENAI_API_KEY`·`OPENAI_BASE_URL`·`ADMIN_TOKEN`을 직접 입력합니다(`sync: false` 항목). `SMTP_*`·`CONTACT_EMAIL`은 필요 시 추가합니다. `.env` 파일은 절대 저장소에 커밋하지 않습니다.
3. **데이터 저장소** — 블루프린트가 만드는 Render 무료 PostgreSQL은 **생성 30일 후 만료**되므로(데이터 소실), 상시 서비스는 Neon 등 관리형 PostgreSQL 접속 문자열로 `DATABASE_URL`을 교체하세요. 정기 백업은 `npm run db:backup`(backend 폴더)으로 `backend/backups/*.sql` 덤프를 만들 수 있습니다.
4. 배포가 완료되면 이 문서의 **배포 주소** 항목에 URL을 추가하세요.
